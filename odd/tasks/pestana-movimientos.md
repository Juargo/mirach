# Movimientos tab — three bucket panes with a visible "Mover" button (iOS and Android)

Objective: add a «Movimientos» tab to both native apps that shows the month's movements in three fixed bucket panes and lets the user move a movement to another category with a visible button. Branch `feat/pestana-movimientos` (base `81e46c09`). Delivery: stacked to main, one slice per unit (iOS, then Android), the user's cached choice in `odd/tasks/android-detalle-y-categorias.md`; forecast about 1,500 authored lines.
Test runners: iOS `cd apps/ios && ./scripts/generate.sh && xcodebuild -project Mirach.xcodeproj -scheme Mirach -destination 'platform=iOS Simulator,name=iPhone 18 Pro' test -only-testing:MirachTests`; Android `cd apps/android && ./gradlew testDebugUnitTest assembleDebug lint --no-daemon`.
Design reference (approved mockups, row 2): https://claude.ai/artifact/1F3a6Hq74qKsH3wVynoduo — «A · En reposo», «B · Mover», «C · Después de mover».

## Specs

Common rules for every spec: no API change; the apps calculate no totals, percentages or states (ADR-001), everything comes from the API; the interface says «Gustos», never «Deseos»; amounts as `$1.234.567` with tabular figures; a null percentage shows «—»; tokens only, square corners, no shadows, colour never alone (`design/README.md`); touch targets of 44 pt / 48 dp; user-facing copy in neutral Spanish, exactly as quoted here.

- **S1 — Tab.** User: "Agreguemos pestaña movimientos." A «Movimientos» tab in the bottom bar. Assumption (approved mockup): it is the second tab, so the order is Resumen, Movimientos, Subir, Categorías, Perfil, with a list icon.
- **S2 — Three panes as an accordion.** User: "cada bucket sea un acordeon y que solo uno quede abierto" and, asked how the screen behaves when the open bucket has many movements, chose «Encabezados siempre visibles»: "Los tres encabezados quedan siempre en pantalla. El bucket abierto ocupa todo el espacio restante y su lista se desplaza por dentro. Cambiar de bucket es siempre un toque." The screen shows the selected month and three panes in the order Necesidades, Gustos, Ahorro. The three headers are always on screen and the screen itself does not scroll; exactly one pane is open, it takes the height the two closed headers leave and scrolls on its own. Tapping a closed header opens it and closes the one that was open. Assumptions: Necesidades is open when the tab opens; tapping the open header does nothing (one pane is always open); the open pane stays through a month change, a move, an undo and a reload; a mark on each header (and «Abierto» / «Cerrado» for screen readers) says which one is open. Each pane has a bar in its bucket colour and a header with the bucket name and, user: "con que solo diga cantidad total y % es suficiente en cada cubo bucket", exactly the bucket total and its percentage of income as `{total} · {porcentaje}` (for example `$569.400 · 52%`), nothing else (no target, no state, no counts). Data: one `GET /api/buckets/{bucket}/detalle?periodo` per bucket, the three in parallel, for one `periodo` resolved once. This replaces the first version (three fixed panes of equal height, nothing collapsing; L5, L6), which the user tried on a phone (L14).
- **S3 — Category rows.** User: "me gustaba más cuando las categorias tenian bien maracada su diferenciación". Inside a pane, each category group of the API is a clearly marked row: a square tile filled with the bucket colour holding the category icon, the category name, «N movimientos» («1 movimiento»), and the subtotal. Groups keep the API order. The «Sin categoría» group (null `categoriaId`) shows with the fallback icon. A category row is not a button on this screen.
- **S4 — Movement rows.** User: "Mejor que todas las transacciones se vean con todos los datos Nombre completo + fecha. Sin necesidad de presionar." Under its category, indented, every movement shows the full description (it wraps, never truncated), the transaction date under it, the amount, and a visible «Mover» button. User: "yo creo que es mejor que sea visible ya que puede que más adelante hacer click sobre el item haga otra acción": the row itself does nothing when tapped; only the button acts. Movements keep the API order.
- **S5 — Move.** «Mover» opens the category sheet for that movement. Assumption: it is the existing sheet of the bucket detail with its existing behaviour unchanged (pick, then «Guardar»; «Aplicar a “{texto}”»; create a category; the «Cambiar de grupo» confirmation «Este movimiento pasará de {bloque actual} a {bloque nuevo} y cambiará el cálculo del mes.» when the picked category belongs to another bucket), not the chip layout drawn in mockup B. Reuse the existing sheet and its state machine; do not re-implement it with a different shape.
- **S6 — After moving.** User: "que la ventan de despues de mover también quede como reposo". After a successful move the same screen stays and the three buckets reload, so the movement appears under its new category and the totals change. A notice reads «Movido a {Bucket} · {Categoría}» with a «Deshacer» action, announced in an accessible status region. «Deshacer» sends the movement back to its previous category with the same reclassify call, reloads, and removes the notice. Assumptions: the notice has no «Deshacer» when the movement came from «Sin categoría» (the API cannot restore a null category) or when the move was saved with «Aplicar a parecidos» (the pattern and the other moved movements cannot be reverted by one call); a failed undo shows an error notice and keeps the data on screen. A move or undo here also reloads Resumen; an import, a deleted statement, a saved profile or a catalog change reloads this tab.
- **S7 — Month.** The title area shows the month and lets the user change it with the existing month selector component. Assumption: the tab opens on the most recent month with data and its month is independent of Resumen's.
- **S8 — States.** Loading («Cargando movimientos…»), error with «Reintentar» (the connection and server messages of the bucket detail), and success. A bucket with no movements keeps its pane and header and shows «Sin movimientos» inside. If any of the three requests fails, the screen shows the error state. Pull to refresh reloads the three.
- **S9 — Large text.** Assumption, following the precedent of the bucket detail: at accessibility text sizes (iOS accessibility sizes; Android font scale ≥ 1.3) the screen becomes one scrolling list with the three headers and the rows of the open pane, so nothing is clipped.
- **S10 — What stays as it is.** User: "Dejemos eso tal como está ahora." Resumen and the bucket detail keep their behaviour, copy and tests unchanged (the bucket detail still says «Movida a …»). User: "arrastrar podría complicar a las personas": no drag and drop anywhere.
- **S11 — Docs.** `docs/catalogo/flujos/inicio-y-movimientos.md` and `docs/catalogo/README.md` describe the new tab and screen as built, and each app's README lists it if it lists screens.
